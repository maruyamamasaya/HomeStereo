# UI改善バックログ

HomeStereoのUIを、Apple Musicを参考にしながら段階的に改善するための作業台帳である。外観の模倣ではなく、情報階層、操作の予測可能性、再生状態の把握しやすさを参考にする。

## 進め方

- 一度に大規模な画面置換を行わず、1件または密接に関連する少数の課題を単位に変更する。
- 各変更で既存の再生、Queue、Library、Renderer制御を維持する。
- 状態は`未着手`、`対応中`、`確認待ち`、`完了`のいずれかとする。
- `完了`はコード変更だけでなく、関連test、macOS build、対象画面の目視確認まで終えた状態とする。
- 実機Rendererが必要な項目は、自動test成功だけで完了にしない。

## P0: 基本導線と状態の理解

### UI-004 再生開始までの導線

- 状態: 完了
- 課題: 「スピーカーを選ぶ」「曲を選ぶ」「再生する」の前提と順序が画面から分からない。
- 完了条件:
  - 未選択の前提条件を画面内で説明する。
  - 無効な再生ボタンに理由を示す。
  - 初回利用者がSidebarを総当たりせず再生開始まで進める。

### UI-005 通信エラーの表示方法

- 状態: 確認待ち
- 課題: 通信切断がモーダルで操作を遮り、失敗箇所と回復方法も分かりにくい。
- 実装メモ: 下部バー上に非モーダルのエラーバナーを追加し、再試行と閉じる操作を提供した。実機切断時の表示確認が残る。
- 完了条件:
  - 一時的な通信失敗を非モーダルに表示する。
  - 再検索、再接続、詳細確認の次操作を提示する。
  - 重要な確認だけをalertとして残す。

### UI-006 Now Playing状態の一本化

- 状態: 完了
- 課題: Queue再生と直接ファイル再生で情報源が異なり、曲名や操作可能状態が一致しない可能性がある。
- 完了条件:
  - Queue、直接ファイル、Renderer側変更で一貫した表示modelを使う。
  - 曲がない状態、読込中、再生中、一時停止、通信不明を区別する。
  - 下部バー、小型プレイヤー、MenuBar、Now Playing連携が同じ状態を示す。

### UI-007 選択中と再生中の区別

- 状態: 確認待ち
- 課題: 曲、スピーカー、Playlistで、単なる選択と現在使用中の項目が見分けにくい。
- 実装メモ: 曲、アルバム、アーティスト、お気に入り、履歴、Queue、Playlistで再生中iconと背景を追加済み。実データでの通し確認が残る。
- 完了条件:
  - 選択、現在再生中、出力先、missingを異なる表現にする。
  - 色だけに依存せず、iconまたはlabelでも判別できる。

### UI-011 アーティスト画面

### UI-030 お気に入り／再生履歴

- 状態: 確認待ち
- 課題: Artworkや空状態がなく、曲の識別、再生中の把握、次の操作が分かりにくい。

  - お気に入り、最近再生、よく聴く、未再生の空状態に次操作を示す。
  - 再生中、ファイルなし、Library未解決を色以外でも区別する。

### UI-012 検索と表示件数

## P1: 再生UI

### UI-013 「再生中」画面の再設計

- 状態: 確認待ち
- 課題: 現在のFormは設定・診断画面に見え、音楽再生画面としての優先順位が弱い。
- 完了条件:
  - Artwork、曲名、Artist、Album、再生位置、基本操作を主役にする。
  - `AVTransport`などの技術情報を通常表示から外す。
  - 診断情報は別のDisclosureまたは画面へ移す。

### UI-014 重複する再生操作の役割整理

- 状態: 確認待ち
- 課題: 下部バー、再生中画面、Queue、Inspector、小型プレイヤーに同じ操作が重複する。
- 完了条件:
  - 下部バーは常用操作、再生中画面は詳細、Queueは曲順編集という役割を明確にする。
  - 同じ状態変更が各画面へ即時反映される。

### UI-015 下部バーのシーク操作

- 状態: 確認待ち
- 課題: 下部バーでは時間を読めるが、再生位置を直接操作できない。
- 実装メモ: 下部バーへ経過時間、シークスライダー、総時間を追加した。ドラッグ中はpolling値で操作位置を上書きせず、操作完了時にSeekを送る。通常幅／狭い幅の目視と実機Seek確認が残る。
- 完了条件:
  - 再生位置と全体時間を視覚的に示す。
  - RendererがSeek非対応または状態不明の場合は安全に無効化する。

### UI-016 下部バーの音量

- 状態: 確認待ち
- 課題: Renderer音量が「再生中」画面にしかなく、常用操作として遠い。
- 実装メモ: 下部バーへ1%刻みの音量操作を追加済み。Sonyステレオ選択時は左右両方へ反映し、L/Rバランスも同じバーから調整できる。実機と狭いwindowでの確認が残る。
- 完了条件:
  - RenderingControl対応時だけ下部バーから調整できる。
  - 操作中の連続SOAP送信を避け、操作完了時に確定する。

### UI-017 Shuffle／Repeatの可視化

- 状態: 確認待ち
- 課題: Queue画面を開かないと現在状態が分からない。
- 完了条件:
  - 現在状態を下部バーまたは再生中画面で確認・変更できる。
  - 選択状態を色だけで表現しない。

## P1: スピーカー

### UI-018 スピーカー一覧の利用者向け表示

- 状態: 確認待ち
- 課題: IP、AVTransport、Device Descriptionなど技術情報が通常操作より目立つ。
- 完了条件:
  - 名前、機種、接続状態、選択状態を主情報にする。
  - IPやservice URLは診断詳細へ移す。

### UI-019 接続状態の定義

- 状態: 確認待ち
- 課題: 検出済み、選択中、再生可能、応答なし、再接続中の区別が弱い。
- 実装メモ: 検出済み、選択中、通信不明、network待機、再接続中、再接続済み、切断をiconと文言で区別し、最終検索時刻と件数を表示した。実機遷移の確認が残る。
- 完了条件:
  - 状態語とiconを統一する。
  - 最終検出時刻または再検索結果を確認できる。

### UI-020 Wireless Stereo状態

- 状態: 確認待ち
- 課題: 2台が独立Rendererなのか、L/Rグループなのかアプリから判断できない。
- 実装メモ: 現行の標準UPnP Device Descriptionから左右構成を安全に確定できないため、Sony機では「UPnP情報からは確認できません」と明示し、L/Rを推測しない。Sony固有serviceの実機調査が残る。
- 完了条件:
  - Sony固有serviceから安全に読める状態を調査する。
  - 確認できる場合だけL/Rまたはグループ状態を表示する。
  - 未確認情報を推測で表示しない。

### UI-021 スピーカーの安定した並び順

- 状態: 確認待ち
- 課題: SSDP応答順によって一覧順が変わる。
- 実装メモ: 選択中を先頭にし、その後をfriendly name、model、安定IDでsortする実装と自動testを追加した。複数実機での再検索確認が残る。
- 完了条件:
  - 選択中を優先し、その後はfriendly nameなど安定したkeyで並べる。
  - 再検索で選択行が不必要に移動しない。

### UI-024 Playlistの識別性

## P2: 全体品質

### UI-025 用語の統一

- 状態: 確認待ち
- 課題: 日本語と`Queue`、`Playlist`、`Favorite`、`Library`、`scan`、`missing`、`Renderer`などが混在する。
- 実装メモ: 利用者向けのスピーカー、音楽フォルダ、バックアップ画面を日本語へ統一し、UPnP／serviceなどは「技術情報」内に限定した。全画面の実データ確認が残る。
- 完了条件:
  - 利用者向け表示と診断用語を分ける。
  - Sidebar、画面title、button、alert、READMEで同じ語を使う。

### UI-026 Toolbar配置規則

- 状態: 確認待ち
- 課題: 検索、並べ替え、追加、再検索などの配置が画面ごとに異なる。
- 実装メモ: 追加／再検索／書き出し／復元をToolbarの主要操作へ寄せ、低頻度・destructive操作をmenuへ移した。狭いwindowとFull Keyboard Accessの確認が残る。
- 完了条件:
  - 主要操作、表示操作、管理操作の順序を統一する。
  - icon-only buttonにはaccessibility labelとtooltipを付ける。

### UI-027 空・読込中・失敗状態

- 状態: 確認待ち
- 課題: 次に何をすべきか示さない空画面や、原因を特定できない失敗表示がある。
- 実装メモ: Library、お気に入り、再生履歴、スピーカー、音楽フォルダ、バックアップ、Queue、Playlistでempty／loading／error／contentを分離した。実データと実機エラーの確認が残る。
- 完了条件:
  - 各主要画面でempty、loading、error、contentを区別する。
  - emptyとerrorには安全な次操作を1つ以上示す。

### UI-028 画面密度と余白

- 状態: 確認待ち
- 課題: 曲一覧、再生画面、Playlistで情報密度が揃っていない。
- 完了条件:
  - 一覧、詳細、設定の各画面で共通の余白と行高を使う。
  - 狭いwindowでも主要操作が隠れない。

### UI-029 AccessibilityとKeyboard

- 状態: 確認待ち
- 課題: 既存対応はあるが、新しい情報階層を含む通し確認が必要。
- 実装メモ: icon-only操作にlabel／helpを補い、再生状態をiconと文言でも表現した。Space、Command-F、Command-Oのcommand実装は維持している。VoiceOverとFull Keyboard Accessの手動通し確認が残る。
- 完了条件:
  - VoiceOverでSidebarから再生まで移動できる。
  - Full Keyboard Access、Space、Command-F、Command-Oを確認する。
  - 選択や再生状態を色だけに依存しない。

### UI-031 音楽フォルダ管理

- 状態: 確認待ち
- 課題: 保存場所、更新の進捗、アクセス権エラーが同じ密度で並び、日常操作と診断情報の優先順位が弱い。
- 実装メモ: 登録数／曲数／自動更新の概要、フォルダカード、空状態、非モーダルエラー、読み込み進捗、折りたたみ詳細へ再構成した。
- 完了条件:
  - 初回利用者がフォルダ追加から曲の読み込みまで理解できる。
  - 更新中、アクセス権喪失、読み込み失敗を区別できる。
  - pathや件数内訳は必要なときだけ確認できる。

### UI-032 バックアップと復元

- 状態: 確認待ち
- 課題: 英語と技術用語が多く、保存対象と復元時の安全性が操作前に分からない。
- 実装メモ: 保存対象／対象外、3段階の利用手順、復元preview、安全な照合結果、非モーダル結果表示へ再構成した。
- 完了条件:
  - 保存されるものと保存されないものを操作前に確認できる。
  - 復元内容と未解決／曖昧な曲を適用前に確認できる。
  - 成功、失敗、確認待ちを画面内で区別できる。
