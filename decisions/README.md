# Architecture Decisions

将来の作業者が「なぜ」をコードだけから判断できない重要事項だけを記録する。連番は`NNNN-short-title.md`とし、少なくとも次を含める。

```text
# NNNN Title
Status: Proposed | Accepted | Superseded
Date: YYYY-MM-DD

## Context
## Decision
## Reason
## Alternatives
## Consequences
```

軽微な実装詳細や毎回の変更はDecisionにせず、`sessions/`へ記録する。既存判断を変える場合は元文書を消さず、後継Decisionから参照する。
